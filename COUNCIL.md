# Council contract

## Interpretation, not genetic foresight

Council questions describe environmental/ecological selection pressures and the energy/reproduction cost tradeoffs of imposed future-birth strategies. `mutationTarget` retains its existing name and palette for API/replay compatibility; its evidence is an advisory trait focus, not permission to direct genetic changes. Mutation tempo controls undirected variation rate and never guarantees advantageous mutations. The orchestrator can select `none`; inactive proposals are not interventions. A same-value patch must not be presented as a changed ecological law merely because it was proposed (graph-version accounting belongs to the engine).

Each actual downstream request reserves quota before the SDK call, including every specialist in a parallel fan-out. Production requires both the per-client Cloudflare Workers Rate Limiting binding (10/minute) and a shared aggregate binding (60/minute); absent, failed, or denied checks prevent model execution and use deterministic fallback. Cloudflare counters are per location and eventually consistent: they are abuse protection, not an exact billing ledger. Account/provider usage controls remain the hard spend backstop.

UI integration: `config.rules.council` is `{version:1,members:[{id,responsibility,scope,activation}]}` (2–6 Jev-selected registry members). `config.rules.councilSetup` holds setup orchestrator provenance. Runtime `decision.council` is `{manifest,orchestrator,members,selectedPatch,calls}`. Each provenance record is `{id,responsibility,scope,model,usage:{input_tokens,output_tokens},evidence:{[question]:{choice,confidence,probabilities}}}`. `decision.usage` aggregates all runtime records. Only applicable members called; records remain in manifest order. Responsibilities: birth_policy (species), self_interaction (species), relationship (named pair), environment. IDs are not universal roles.

Setup first builds a validated ecosystem, then Jev selects count and ranks scoped registry responsibilities, plus activation conditions. Runtime orchestration selects applicable specialists and chooses the single patch owner and bounded timing; selected specialists execute concurrently. Reconciliation accepts species birth policies and at most one selected scoped graph patch. Other proposals remain evidence, never engine authority. No cell control, lineage introductions, rescues, or automatic ecological policy changes. Failed councils abstain atomically. Replay stores manifest/setup evidence inside the initial graph and runtime provenance inside the ordered ledger; replay makes no inference calls.
